# 1.2.7 loop state

This file is read at the start of every iteration. The coordinator owns it.

**Branch:** release-1.2.7.

**Contract:** docs/plans/1.2.7-gates.json, the named tests per milestone. Only the coordinator edits it.

**Gate:** `.loop/gate127.sh <M> <base> [last]` (in the main checkout, untracked) runs the machine checks, then `gate127.sh ci` checks GitHub CI after the push. A milestone can't be marked done without both.

## Roles

| Role | Who | Does | Never |
|---|---|---|---|
| Maker | a fresh implementer per milestone | builds the items with their named tests; reads this file and the plan first | grades its own work; edits the contract; deletes or weakens a test; pushes |
| Checker 1 | the gate (machine) | runs the checks in gate127.sh, one PASS/FAIL line per check | |
| Checker 2 | a fresh reviewer subagent each round (M0, M4, M6, M9, M10 and M13 add a security reviewer) | reads only the plan, the diff BASE..HEAD and the gate output, never the maker's report; returns findings as high, medium or low, each with file:line | |
| Coordinator | Claude, main session | runs the loop, pushes after the gate passes, reports to the owner, updates this file | |

## Stop rules

- **Done:** the gate is all PASS, CI is green, and the reviewer has no high or medium findings left.
- **Budget:** at most 4 build/fix rounds per milestone. When a 5th would be needed, stop and report to the owner with the per-check report.
- **Blocked:** the same check fails twice with the same cause → stop and report it. Don't retry blindly.
- **Never:**
  - tag, merge to main, publish or upgrade the live install without the owner's yes;
  - touch the live containers;
  - run anything on the Mac.

## Lessons from 1.2.6 (apply every milestone)

- Measurable targets are in the contract before the build; results go into bench/RESULTS.md as they are measured.
- Every address a person is given is opened in the release run (does it route?).
- Reviewers check the sentences shown to people for truth, not only the code.
- The owner tries each visible milestone on the server before the next builds on it (a short click-through list with what was assumed).
- Before an upgrade of the live install: check that every commit the live install runs is in the release (1.2.6 nearly lost one 1.2.5 fix).
- A model key goes by environment over ssh stdin only, never into a file, also not in a throwaway container.
- Owner sketches first: M3, M7, M8, M11, M12.
