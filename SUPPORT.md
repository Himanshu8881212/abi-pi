# SUPPORT: how Pi covers the eight harness parts

Pi `1.3.0` (`@earendil-works/pi-coding-agent`, the renamed `pi-mono` coding agent), installed user-level at
`~/.pi/agent` before this work. Docs read: `docs/{how-pi-works,extensions,mcp,skills,prompt-templates,settings,
configuration,models,custom-provider,rpc,rpc-extension-ui,json}.md` and `examples/extensions/{subagent,permission-gate,
dynamic-tools,provider-payload,hello}`.

## Model

| Setting | Value |
|---|---|
| Provider | `cliproxy` (registered by `.pi/extensions/abi/index.ts` with `pi.registerProvider`, API `openai-responses`) |
| Endpoint | the local CLIProxyAPI (`~/cliproxy-server-credentials.txt`: base URL and key read at request time by `scripts/creds.py`, never copied) |
| Model ID | `gpt-6.1-sol` (Pi also lists `openai/gpt-6.1-sol`, but that provider's ChatGPT sign-in had expired: `invalid_grant`) |
| Reasoning effort | `medium` (`.pi/settings.json` `defaultThinkingLevel`; `low` benchmarked: no faster, see `bench/RESULTS.md`) |
| Where | `.pi/settings.json`: `defaultProvider cliproxy`, `defaultModel gpt-6.1-sol`, `enabledModels ["cliproxy/gpt-6.1-sol"]`; subagents name `model: cliproxy/gpt-6.1-sol` |

## The eight parts

| Part | Native in Pi? | Add-on installed | Own extension / file | How it was checked |
|---|---|---|---|---|
| 1. System prompt | yes: `.pi/SYSTEM.md` replaces the base prompt; extensions edit `systemPromptOptions.sections` in `before_agent_start` | none | `.pi/SYSTEM.md` (ABI's Main Agent instructions); `abi_context` section (memory, prefs, model digest, today/time zone last) in `.pi/extensions/abi/index.ts` | `pi -p "Which ABI projects can I see?"` answers as ABI; benchmark runs |
| 2. Rules | yes: `AGENTS.md` context file (loaded from the cwd) | none | `AGENTS.md`; enforcement in the extension (`tool_call` guard, confirmation bridge, grounding) | `tests/test_guardrails.py` (live) |
| 3. Memory | no long-term store in Pi (sessions only) | none needed: ABI's `remember`/`forget`/glossary over MCP are the store | prompt injection of ABI memory (`GET /api/memory`); Pi-side preferences tool `abi_prefs` (`~/.abi-pi/prefs-<user>.json`, mode 600, outside git) | `abi_prefs set/get`; memory section in the prompt (`before_agent_start`) |
| 4. Tool notes | partly: MCP `exposure: deferred` + `toolExposure` per tool; `pi.setActiveTools` | none | `harness/areas.json` (ABI's CORE/AREAS, generated by `scripts/gen_areas.py` from ABI's source), `harness/notes/<group>.md`, `abi_tools` loader + keyword preload (ABI's D-71 regexes) | `abi_tools` returns notes and activates tools; benchmark shows the preload saves a turn |
| 5. Skills | yes: Agent Skills in `.pi/skills/<name>/SKILL.md`, on demand, `/skill:name` | none | 10 skills: load-data, profile-clean, build-model, measures, build-report, writeback-planning, forecast-ml, flows-alerts, custom-agent, promote | the agent reads `writeback-planning` before a target change (scenario 3 trace); groups ship their playbooks with the notes |
| 6. Scripts | n/a (Pi runs tools; scripts are ours) | none | `scripts/creds.py` (sign-in/token at request time), `scripts/abi.py` (health, workspace, project skeleton, load, sync, `cli validate/diff/apply/watch`), `scripts/ground.py` (grounding checker), `scripts/render.py` (HTML views), `scripts/bench.py` | `abi.py health`; `tests/test_layout.py`, `tests/test_ground.py` |
| 7. Subagents | no (Pi ships an example extension, not a built-in) | official example `examples/extensions/subagent` from pi-coding-agent 1.3.0, copied to `.pi/extensions/subagent/` (3 lines patched: project agents by default, `ABI_PI_ALLOWED`/`ABI_PI_AGENT` env per child) | `.pi/agents/{data-engineer,analyst,ml,automation}.md` generated by `scripts/gen_agents.py` (each lists only its groups' tools); ABI's own agents via `run_agent` | "Use the analyst subagent to list yt's reports": child ran `list_reports` only, logged as `agent: analyst` |
| 8. Plugins / MCP | yes: built-in MCP client (streamable HTTP, `.pi/mcp.json`, header from a `!command`) | none | `.pi/extensions/abi/index.ts`: confirmation bridge (MCP says "do it in the app" → harness asks the person with ABI's message/preview → REST `X-Abi-Confirm`), status line, provider, schema fix | `pi mcp list` → `abi: connected, 160 tools`; scenario 3 approval showed ABI's old → new preview and nothing changed on "no" |

No community package was installed: everything missing was a small extension or came from Pi's own examples, so
nothing phones home. `.pi/settings.json` turns off Pi's `bash` (and the extension blocks `bash`/`powershell`), so file
tools are the only local tools and they stay inside this folder.

## Pi project trust

Pi loads `.pi/` only for trusted folders. This folder was added to `~/.pi/agent/trust.json` (the same entry Pi writes
when you accept its trust prompt).
